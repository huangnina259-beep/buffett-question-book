This app generates new answers from retrieved library material and supports follow-up questions. You can ask in English or Chinese. Answers are in English, with original English source excerpts and explicit limits.

  1. Keep the folders together.

    Keep this app beside the complete 巴菲特知识库 folder. Its source links and search depend on that library.

  2. Double-click the launcher.

    On macOS, open Start Buffett Questions.command. It requires Python 3.9 or later and uses Codex’s bundled Python when available. Keep the Terminal window running while you use the app.

  3. Open the local address.

    Use the address printed in Terminal, normally http://127.0.0.1:8795. Press Ctrl + C in Terminal to stop the server.

Open the default local address ↗Start the launcher first. Opening web/index.html directly cannot generate answers.

Uses your existing Codex account and allowance. Installed, signed-in Codex and network access to its model service are required. Generation consumes that account’s usage allowance; this is not a free standalone assistant. The website runs locally on 127.0.0.1 and has not been publicly deployed.

Ask, read, follow up.

  • Enter a question of 3–2,000 characters. The visible stages reflect planning, retrieval, writing and checking.
  • Open the numbered citations beside a paragraph to inspect the excerpt, retrieved text, source status and original-source links.
  • Ask a follow-up to the selected answer. Up to four recent answers are included as context; long answers may be shortened.
  • Use New question for a fresh topic. Earlier answers remain selectable during the visit.

A bounded source collection.

The current base library has 118 sources with imported text. Retrieval uses eligible passages and source boundaries within that collection. This count is not approval of every sentence or proof that an entire source is reliable.

The collection includes Berkshire Hathaway shareholder letters and CNBC Buffett Archive meeting and interview material. Inspect the source library for publisher links, archived originals and extraction notes. Generated answers and editorial labels are separate from those originals.

Reference-only pages, unverified third-party speech transcripts and disallowed extraction units are excluded. Coverage gaps remain. Check the app’s available-source scope and each answer’s retrieval details for what was actually used.

Evidence can run out.

Each question uses a finite selection of retrieved contexts. Relevant qualifications, contrary passages or later comments can be missed. A search miss does not establish that Buffett never discussed a subject.

There is no live web or current-market feed. Historical statements retain their dates, audiences and conditions; they do not establish today’s valuations or your personal suitability.

Read the review limits.

Exact citation checks and a separate model review assess the proposed answer against its retrieved passages. This is not human verification, audio authentication or a complete review of Buffett’s views.

An answer may be partial, insufficient, outside the library’s scope or withheld after failed checks. The generator is instructed to ground practical implications in the selected evidence. These checks can still miss errors or conditions; inspect the original passages before applying an answer.

What is sent, and what stays in this page.

Model requests include your question, limited conversation history and selected public source excerpts. They are sent through the installed Codex account to its model service. Local browsing does not make generation an offline operation.

The browser’s question list exists only in page memory; reloading clears it. The local server holds jobs in memory. Codex may create operational records in the app’s runtime/ folder, and its runtime and model service have their own data handling. Browser-memory behavior is not a promise about their retention.

If an answer does not arrive

Keep Terminal running and check the app’s connection message. If Codex needs sign-in, sign in and restart the app. If the usage allowance is exhausted, wait for availability; a new question still consumes model usage. For a timeout, try a narrower question. After a connection interruption, use Reconnect to this question when offered, so the existing job is checked without submitting it again.
